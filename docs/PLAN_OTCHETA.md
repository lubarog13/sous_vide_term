## ВВЕДЕНИЕ

**Объём:** 1–2 страницы.

**Что включить:**

- **Актуальность:** точная поддержание температуры при длительной готовке (су-вид, йогурт, творог и т.п.); удобство дистанционного управления с телефона.
- **Объект исследования:** программно-аппаратный комплекс термостата.
- **Предмет:** алгоритмы измерения и контроля температуры, обмен данными по Bluetooth, мобильное приложение управления.
- **Цель работы:** разработать устройство с поддержанием заданной температуры и управлением параметрами с мобильного приложения.
- **Задачи** (4–6 пунктов):
  - подобрать и описать аппаратную часть;
  - разработать прошивку микроконтроллера;
  - реализовать протокол обмена по Bluetooth;
  - создать мобильное приложение (Android);
  - реализовать программы готовки и таймер;
  - проверить работоспособность комплекса.
- **Кратко о результате:** ESP32, датчик DS18B20, LCD, локальное и дистанционное управление, приложение Flutter.
- **Структура отчёта** — по одному предложению на раздел.

## ПРОГРАММНАЯ ЧАСТЬ

Раздел разделить на **две подсистемы**: прошивка микроконтроллера и мобильное приложение.

### Прошивка Arduino (ESP32)

#### Используемые библиотеки и модули

| Библиотека / модуль | Назначение |
|---------------------|------------|
| `LiquidCrystal_I2C` | Вывод на LCD |
| `GyverDS18` / OneWire | Опрос DS18B20 |
| `ezButton` | Обработка кнопок с антидребезгом |
| `BluetoothSerial` | Связь SPP с телефоном |

**Основные переменные состояния:**

- `currentTemperature`, `targetTemperature`, `temperatureOffset` — измеренная, целевая температура и допуск;
- `timeMinutes`, `timerRunning`, `timerStartedAtMs`, `timerStartMinutes`, `timerFinishedBeeped` — таймер и обратный отсчёт;
- `shakerEnabled`, `shakerRunning` — флаг и состояние перемешивания.

**Ключевые константы:**

- `TEMPERATURE_STEP = 0.5` — шаг изменения целевой температуры кнопками INC/DEC;
- `TEMPERATURE_MIN = 0`, `TEMPERATURE_MAX = 100` — диапазон целевой температуры с циклическим переходом;
- `OFFSET_STEP = 5` — шаг изменения времени энкодером (минуты);
- `TIMER_MINUTES_MIN = 0`, `TIMER_MINUTES_MAX = 1440` — диапазон таймера (0–24 ч);
- `TEMP_UPDATE_TIME = 5000` — период опроса DS18B20 (5 с).

#### Режимы работы

1. **Ожидание** — периодический опрос DS18B20 (`ds.tick()`), вывод `TT`, `Of`, `TC` и таймера на LCD, передача состояния по Bluetooth (`sendTemperatureToSerial()`).
2. **Задание параметров** — приём `Tt:`, `O:`, `S:`, `M:` по Bluetooth; локально: кнопки INC/DEC меняют `targetTemperature`, энкодер меняет `timeMinutes` (если таймер не запущен).
3. **Контроль в допуске** — при активном таймере (`timerRunning == true`) сравнение `currentTemperature` с диапазоном `[Tt − O, Tt + O]`; управление LED и реле (`PIN_RELAY`).
4. **Работа таймера** — команды `M:<minutes>`, `START`, `STOP` и локальная кнопка таймера; обратный отсчёт в `runTimer()`.
5. **Перемешивание** — при `shakerEnabled && timerRunning` двигатель включается через `analogWrite(MOT_PIN1, 128)`.

#### Специальные звуковые сигналы

- короткий сигнал (1000 Гц, 500 мс) при запуске таймера с кнопки;
- короткий сигнал (500 Гц, 500 мс) при команде `START` с телефона;
- сигнал (500 Гц, 500 мс) при входе температуры в допуск во время работы таймера;
- непрерывный сигнал (1000 Гц) при выходе из допуска;
- сигнал (1000 Гц, 500 мс) по окончании таймера.

#### Управление светодиодами и реле

- `LED_NORMAL_PIN` — температура в допуске (только при работающем таймере);
- `LED_ALARM_PIN` — отклонение от допуска;
- `LED_TIMER_RUNNING_PIN` — активный отсчёт таймера;
- `PIN_RELAY` — включается, если температура ниже допуска; выключается в допуске или при перегреве; сбрасывается при `STOP` и окончании таймера.

#### Обработка команд Bluetooth

- чтение строки: `ESP_BT.readStringUntil('\n')`;
- разбор префиксов `Tt:`, `O:`, `S:` и команд таймера в `handleTimerCommands()`;
- ключевые функции: `handleEncoder()`, `toggleTimerFromButton()`, `runTimer()`, `checkTemperature()`, `sendTemperatureToSerial()`.

#### Экраны и функции

**Главный экран (`MyHomePage`):**

- сканирование и подключение по Bluetooth Classic (`CustomBluetoothService`, фильтр по имени устройства);
- отображение текущей (`Ct`) и целевой (`Tt`) температуры (°C / °F);
- выбор целевой температуры и допуска через `flutter_picker_plus`;
- переключение перемешивания `S`;
- таймер: выбор длительности (часы:минуты), старт / пауза / сброс, виджет `TimerCountdown`, индикатор прогресса;

- сохранение и обновление пользовательской программы в SQLite;
- сохранение состояния сессии в `shared_preferences` (`current_hours`, `current_minutes`, `current_temperature`, `current_temperature_offset`, `current_shaker_enabled`, `selected_program`, `device`).

**Вкладка «Программы» (`ProgramList`):**

- список из локальной БД (10 предустановленных + пользовательские);
- выбор программы переносит параметры на главный экран через `SharedPreferences`.

**Настройки (`Settings`):**

- тёмная / светлая тема (`themeModeNotifier`);
- единицы °C / °F;
- имя Bluetooth-устройства для фильтра при сканировании;
- руководство пользователя и пользовательское соглашение (`utils/texts.dart`).

#### Протокол обмена с устройством

Текстовые команды, каждая строка завершается `\n`.

| Направление | Формат | Описание |
|-------------|--------|----------|
| → устройство | `Tt:<temp>` | целевая температура |
| → | `O:<offset>` | допуск (гистерезис) |
| → | `S:0` / `S:1` | перемешивание выкл/вкл |
| → | `M:<minutes>` | длительность в минутах |
| → | `START` / `STOP` | запуск / остановка таймера |
| ← устройство | `Tr:0` / `Tr:1` | таймер остановлен / идёт |
| ← | `Ct:<temp>` | текущая температура |
| ← | `Tt:`, `O:`, `M:`, `S:` | эхо параметров для синхронизации |

Устройство отправляет блок из 6 строк при каждом обновлении температуры (`sendTemperatureToSerial()`). Приложение разбирает входящий поток построчно в `_parseReceivedMessage()`.

**Пример диалога для отчёта:**

```
Приложение →  Tt:65.0
              O:0.5
              S:0
              M:60
              START
Устройство ←  Tr:1
              Ct:23.5
              O:0.5
              Tt:65.0
              M:60
              S:0
```

## ПРОЦЕДУРЫ ИНИЦИАЛИЗАЦИИ И СБРОСА

### Прошивка (`setup()`)

1. `Serial.begin(9600)`.
2. `ESP_BT.begin("SmartThermostat")` — запуск Bluetooth SPP.
3. `lcd.init()`, `lcd.backlight()`, `lcd.clear()`.
4. Настройка пинов: энкодер, кнопки INC/DEC/таймер (`INPUT_PULLUP`), LED, зуммер, реле, двигатель (`OUTPUT`).
5. Инициализация `ezButton` для энкодера (`button.setDebounceTime(100)`).
6. DS18B20: `setResolution(12)`, `setPeriod(TEMP_UPDATE_TIME)` — разрешение 12 бит, период 5 с.
7. Начальные значения: `targetTemperature = 20.0`, `temperatureOffset = 0.5`, `timeMinutes = 0`.

### Мобильное приложение

- первый запуск: создание БД SQLite (`openDatabase`, version: 1), импорт `initialData.json`;
- загрузка настроек из `shared_preferences` (тема, °C/°F, имя устройства, выбранная программа, параметры сессии);
- автоподключение к последнему устройству (JSON в `shared_preferences`, ключ `device`);
- запрос разрешений Bluetooth и геолокации (Android) в `_requestPermissions()`.

### Сброс и остановка

- команда `STOP`: остановка таймера, сброс `shakerRunning`, выключение реле, `noTone(BUZZER)`;
- команда `M:<minutes>`: новая длительность без автоматического старта;
- локальный сброс: кнопка таймера на устройстве (`toggleTimerFromButton()`), кнопки сброса/остановки в UI приложения (`_stopTimer()`, `_resetTimer()`).

## СТРУКТУРА ГЛАВНОГО ЦИКЛА

### Arduino — функция `loop()`

Рекомендуется блок-схема или нумерованный алгоритм:

1. `button.loop()`, `handleEncoder()` — опрос энкодера, изменение `timeMinutes`.
2. Обновление LCD: `TT`, `Of`, `TC`, таймер `ЧЧ:ММ`.
3. Приём данных по Bluetooth → разбор `Tt:`, `O:`, `S:`, `handleTimerCommands()`.
4. `incBtn.loop()`, `decBtn.loop()`, `timerBtn.loop()` — кнопки INC/DEC (±`TEMPERATURE_STEP` к `targetTemperature`), кнопка таймера.
5. Логика перемешивания: `analogWrite` на `MOT_PIN1`/`MOT_PIN2` при `shakerEnabled && timerRunning`.
6. `runTimer()` — обратный отсчёт, LED таймера, сигнал по окончании.
7. `checkTemperature()` — опрос DS18B20, сравнение с допуском, LED, зуммер, реле, `sendTemperatureToSerial()`.

### Мобильное приложение

Отдельная схема потока:

1. инициализация UI и состояния (`_initPrefs()`, загрузка программы из БД);
2. сканирование и подключение к Bluetooth-устройству;
3. подписка на поток входящих строк (`CustomBluetoothService.receivedData`);
4. парсинг ответов в `_parseReceivedMessage()` (`Ct`, `Tr`, `Tt`, `O`, `M`, `S`);
5. обновление интерфейса и индикатора прогресса;
6. отправка команд при действиях пользователя (`_sendCommand()`);
7. обратный отсчёт таймера на стороне UI (`TimerCountdown`) с синхронизацией с устройством.

**Общая схема:** «приложение ↔ Bluetooth ↔ ESP32» + две детализирующие схемы для прошивки и приложения.

## ОГРАНИЧЕНИЯ И ВОЗМОЖНЫЕ РАСШИРЕНИЯ

### Ограничения текущей реализации

- целевая платформа — **Android** (Bluetooth Classic);
- текстовый протокол без контрольных сумм и подтверждения доставки;
- период обновления температуры ~5 с (`TEMP_UPDATE_TIME = 5000`);
- управление нагревателем (реле) активно **только при работающем таймере**;
- пороговое включение/выключение реле (без PID-регулирования);
- одно Bluetooth-подключение, нет облачного доступа;
- зависимость от сопряжения устройств и разрешений на телефоне;
- длительность в БД хранится отдельными полями `hours` и `minutes`, а по Bluetooth передаётся суммарно в минутах (`M:`).

### Возможные расширения

- PID-регулирование вместо порогового включения/выключения реле;
- Wi‑Fi / MQTT, веб-интерфейс;
- график температуры и журнал сессий в приложении;
- несколько датчиков, аварийное отключение при перегреве;
- поддержка iOS (с оговоркой об ограничениях Bluetooth Classic).

## ПРИЛОЖЕНИЯ

### Приложение А. Схемы программно-аппаратного комплекса

- структурная схема системы;
- принципиальная схема (ESP32, DS18B20, LCD, реле, LED, кнопки, энкодер);
- фото макета (при наличии);
- схема связи: приложение — Bluetooth — ESP32.

### Приложение Б. Листинг программного кода

- **Б.1** — `arduino/sketch_may17b.ino` (полностью или основные фрагменты по согласованию с преподавателем);
- **Б.2** — ключевые файлы приложения:
  - `lib/main.dart` (обработка Bluetooth, таймер, UI);
  - `lib/services/bluetoothService.dart`;
  - `lib/database.dart`;
  - `lib/programModel.dart`.

### Приложение В (опционально)

- скриншоты приложения (главный экран, программы, настройки);
- таблица предустановленных программ из `assets/initialData.json`;
- пример лога обмена (Serial Monitor / лог BT).

## Отличия от типового отчёта (RFID / метеостанция)

В данном проекте вместо RFID и метеостанции акцент делается на:

- двусторонний **Bluetooth-протокол**;
- **мобильное приложение** (отдельный крупный подраздел);
- **таймер и программы готовки**;
- назначение системы — **термостат / су-вид**.
